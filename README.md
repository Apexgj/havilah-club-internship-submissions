# Havilah Club Internship — Submission Repository

This is the official submission repository for the Havilah Club 8-week AI & Robotics Internship Programme. All task submissions are made through Pull Requests from your personal fork of this repository.

> New here? Start with the [Setup and Git Guide](./SETUP.md) — it walks you through every step from installation to opening your first PR.

---

## How Submissions Work

You do not push directly to this repository. Instead, you:

1. **Fork** this repository to your own GitHub account.
2. **Clone** your fork to your computer.
3. **Fill in** your `STUDENT.md` profile and commit it.
4. **Complete** each task in the correct folder.
5. **Push** your work to your fork.
6. **Open a Pull Request** from your fork back to this repository.

This workflow is how professional developers collaborate on shared codebases. Every PR you open is a record of your weekly submission and will be reviewed by your instructor.

## Step-by-Step Submission Guide

### Step 1 — Fork this repository

1. Go to [github.com/Havilah-Blockchain-Studios/havilah-club-internship-submissions](https://github.com/Havilah-Blockchain-Studios/havilah-club-internship-submissions).
2. Click the **Fork** button in the top-right corner.
3. Under "Owner", select your personal GitHub account.
4. Leave the repository name unchanged and click **Create fork**.

You now have your own copy of this repository at `github.com/your-username/havilah-club-internship-submissions`.

### Step 2 — Clone your fork

Clone **your fork**, not the original repository. Replace `your-username` with your actual GitHub username.

```bash
git clone https://github.com/your-username/havilah-club-internship-submissions.git
cd havilah-club-internship-submissions
```

### Step 3 — Fill in your student profile

Open `STUDENT.md` and fill in every field: your full name, GitHub username, email, cohort, and learning objective. Then commit it:

```bash
git add STUDENT.md
git commit -m "feat: add student profile"
git push
```

This is required before any task work. It tells instructors who the submission belongs to.

### Step 4 — Complete your tasks

Work on each day's task in its designated folder. See [SETUP.md](./SETUP.md) for the full daily workflow (edit → test → commit → push).

Only edit files inside your assigned day folder. Do not modify `test_main.py` or `test_submission.py`.

### Step 5 — Open a Pull Request

Once you have completed all tasks for the week and pushed your work, open a Pull Request:

1. Go to your fork on GitHub: `github.com/your-username/havilah-club-internship-submissions`.
2. Click the **Contribute** button, then **Open pull request**.
3. Make sure the base repository is `Havilah-Blockchain-Studios/havilah-club-internship-submissions` and the base branch is `main`.
4. The PR description will be pre-filled with a template — **fill in every section**:
   - Your full name and GitHub username
   - The cohort and week
   - A checklist of tasks completed
   - A link to your social media post for each day
5. Click **Create pull request**.

### Step 6 — Wait for automated checks

After opening the PR, GitHub will automatically run submission checks on each day's work. You will see the results in the **Checks** section at the bottom of the PR page.

- **Green checkmark** — that day's submission is complete and all required files are present.
- **Red X** — something is missing or has an error. Click the failing check to read the exact error message. Fix the issue in your fork, commit, and push — the checks will re-run automatically on the same PR.

All checks must pass before your PR is reviewed by your instructor.

## Automated Checks

The checks run on every push to your fork and on every PR. They verify submission completeness only — they do not grade the quality of your work.

| Day | What is checked |
|-----|-----------------|
| 11 | `main.py` is present, not empty, and has no syntax errors |
| 12 | `main.py` is present, not empty, and `calculate_grade` is defined |
| 13 | `main.py`, `data/sample.csv`, and `data/output.csv` are all present and non-empty |
| 14 | `main.py` is present, `import requests` is used, `.env.example` is committed, `.env` is not |
| 15 | `main.py` is present, `README.md` is filled in with no placeholder text, `data/` folder exists |

Before opening your PR, confirm all of the following:

- [ ] `STUDENT.md` is filled in and committed
- [ ] All five `main.py` files are complete and have no syntax errors
- [ ] `data/output.csv` has been committed (Day 13)
- [ ] `.env.example` is committed and `.env` is not (Day 14)
